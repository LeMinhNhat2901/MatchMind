# MatchMind Tactical Knowledge Base

`concepts/` holds every `TacticalConcept` entry the RAG retriever draws on
(`matchmind/scripts/build_kb.py` embeds all of these into ChromaDB — that's
step 5 of the pipeline described below).

```
concepts/
  attacking/    hand-written — 12 concepts
  defensive/    hand-written — 10 concepts
  spatial/      hand-written —  8 concepts
  wikipedia/    generated by build_kb_wikipedia.py (see below)
  youtube/      generated by build_kb_youtube.py   (see below)
```

## Schema

`TacticalConcept` (v2, 2026-09) — `category` is one of a fixed 7-bucket taxonomy:
`fundamentals | attacking | defending | transitions | formations | individual |
terminology`, with a free-text `subcategory` for the specific family (e.g.
`high_press`, `half_space`, `433`). Beyond the original fields (`title`,
`content`, `conditions`, `objective`, `possible_actions`, `contraindications`,
`trigger_conditions`), each concept also carries a one-sentence `definition`
(distinct from the longer `content`), `spatial_requirements` (team-shape
preconditions), `player_behaviours` (individual actions that make it work),
and `related_concepts` (informal cross-links to other concepts). All new
fields are optional — see `scripts/migrate_kb_taxonomy.py` for the one-off
remap that moved the original 66 concepts from the v1 category vocabulary
(`attacking_movement`/`defensive_organization`/`spatial_principles`/
`technical_skill`/`general_terminology`) to v2; they were NOT backfilled with
the new optional fields (definition/subcategory/spatial_requirements/
player_behaviours/related_concepts), only new concepts get those automatically.

## Provenance

- **`attacking/`, `defensive/`, `spatial/`** — original, hand-written for
  this project. No `source` field.
- **`wikipedia/`** — adapted from Wikipedia, **CC BY-SA 4.0**. Each concept's
  `content` is an LLM-generated paraphrase (not a verbatim copy) of the
  source article's extract, restructured into the `TacticalConcept` schema.
  Every file in this folder carries a `source` field: `{name, url, license,
  retrieved_at}` citing the exact article.
- **`youtube/`** — adapted from YouTube video transcripts (channel-supplied,
  not auto-discovered). `content` is likewise an LLM-generated paraphrase of
  a transcript chunk, never the transcript text itself. `source.license` is
  `"fair-use paraphrase"` and `source.url` is a timestamped link back to the
  moment in the video the concept was drawn from.

If you reuse this repo's Wikipedia-derived concepts elsewhere, CC BY-SA 4.0
requires attribution and share-alike — keep the `source` field intact.

## Pipeline

This follows the 5-step pipeline from `knowledge_bonus.md`: steps 1-4 are
the two ingestion scripts below; step 5 (embed + upsert into ChromaDB) is
the existing `matchmind.scripts.build_kb`.

### Wikipedia (primary source — structured, clearly licensed)

Uses 3 pre-existing, community-curated Wikipedia categories instead of
crawling arbitrary sites:

| Category | ~articles | maps to |
|---|---|---|
| `Category:Association football tactics` | 27 | `attacking_movement` / `defensive_organization` (LLM decides per article) |
| `Category:Association football terminology` | 211 (noisy — trivia mixed in) | `general_terminology`, or skipped if not tactical |
| individual skills linked from *List of association football skills* | ~24 | `technical_skill` |

```bash
conda activate matchmind

# 1) See what would be pulled in, no LLM calls, nothing written:
python -m matchmind.scripts.build_kb_wikipedia --dry-run

# 2) Smoke test a handful end-to-end:
python -m matchmind.scripts.build_kb_wikipedia --limit 5

# 3) Full run (~50-80 concepts after the relevance filter drops trivia):
python -m matchmind.scripts.build_kb_wikipedia --max-per-category 40 --max-skills 32

# 4) Embed the new concepts:
python -m matchmind.scripts.build_kb --rebuild
```

Step 3 (the LLM call) does two things per article: (a) decides whether it's
actually a usable tactical/positional concept — most of the 211 terminology
pages are trivia ("2–0 lead is the worst lead", "4th place trophy") and get
skipped — and (b) paraphrases the ones that pass into the `TacticalConcept`
schema. Re-running the script is idempotent: it skips any `concept_id`
already on disk.

### YouTube (optional, separate — supply your own video list)

`knowledge_bonus.md` also asked about an automated YouTube → NotebookLM
pipeline. That idea was **dropped**: NotebookLM has no public API for the
free tier, only an unofficial reverse-engineered one running on a personal
Google session cookie, which is a ToS grey area and can break without
warning. Instead this uses the same idea the doc lands on —
`youtube-transcript-api` (official captions, free) + the LLM already wired
into the project — for the same end result without the fragile dependency.

This script does **not** auto-discover channels/videos — you provide a
curated list, so every concept's `source` can cite a real channel name:

```bash
conda activate matchmind
pip install youtube-transcript-api   # not installed by default

python -m matchmind.scripts.build_kb_youtube --urls-file my_videos.txt
python -m matchmind.scripts.build_kb_youtube --url "Tifo Football | https://www.youtube.com/watch?v=XXXXXXXXXXX"

python -m matchmind.scripts.build_kb --rebuild
```

`my_videos.txt` — one video per line, `Channel Name | URL` (channel name is
optional, `#` comments and blank lines are ignored):
```
Tifo Football | https://www.youtube.com/watch?v=XXXXXXXXXXX
https://youtu.be/YYYYYYYYYYY
```

Each video's transcript is split into ~3000-character chunks; each chunk is
independently judged and paraphrased the same way as a Wikipedia article, so
a single video can yield anywhere from 0 to several concepts.

## Reviewing what got generated

LLM output quality varies — skim new files under `concepts/wikipedia/` or
`concepts/youtube/` before trusting them in production, the same way you'd
review any auto-generated content. Nothing here is embedded into ChromaDB
until you run `matchmind.scripts.build_kb --rebuild`.
